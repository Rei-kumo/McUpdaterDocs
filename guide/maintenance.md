# 后续维护

## 合并更新包（清理历史）

随着版本迭代，`updates/incremental/` 目录下会积累大量增量包，`updates/full/` 下也会保留所有全量包。你可以定期清理旧版本以节省磁盘空间，但注意不要删除客户端可能需要的包。

### 安全删除策略

- **保留最近 N 个版本的全量包**（例如最近 3 个版本）。
- **保留每个版本的第一个增量包**（从上一版本到本版本的增量包），因为客户端可能直接从上一版本升级。
- **删除更早的增量包**和**更早的全量包**。

### 使用回退功能清理

服务端提供了**回退到指定版本**的功能，该功能会删除指定版本之后的所有版本（包括增量包和全量包），并将当前工作空间回退到该版本的状态。

1. 在交互菜单中选择 `7. 回退到指定版本`。
2. 输入要回退的目标版本号（例如 `1.2.0`）。
3. 确认后，程序会：
   - 删除所有高于 `1.2.0` 的版本（包括快照、全量包、增量包）。
   - 重新生成目标版本的目录包。
   - 更新版本列表。

这相当于将版本库“重置”到过去的某个时间点，适合清理大量无用版本。

### 手动清理

如果你只想手动删除某些包，请遵循以下原则：

- **删除全量包**：例如删除 `updates/full/1.0.0.zip` 后，客户端无法从旧版本一步到位更新到最新（但可以通过增量包链逐步更新）。建议至少保留最新版本的全量包。
- **删除增量包**：如果删除了 `updates/incremental/1.0.0_to_1.1.0.zip`，客户端从 `1.0.0` 更新到 `1.1.0` 时会失败（但仍可下载全量包 `1.1.0.zip`）。建议保留所有增量包，或确保对应的全量包存在。

### 压缩包瘦身

如果你的项目包含大量小文件，目录分包（`updates/packages/` 下的 zip）会比较多。可以定期重新生成这些包（通过执行 `McUpdaterServer.exe scan` 再执行 `version` 命令重新生成当前版本），它们会被自动覆盖。

## 版本快照管理

每个版本的快照保存在 `updates/snapshots/<version>.json` 中。如果你不再需要某个版本，建议通过**版本管理器**删除（交互菜单中的删除功能），而不是手动删除文件，否则 `versions.json` 中还会残留记录，可能导致 API 返回不存在的版本。

## 日志与监控

- 服务端日志默认写入 `./logs/server.log`，可通过 `config/server.json` 中的 `log_file` 修改。
- 客户端日志写入 `./logs/updater.log`（相对于游戏目录）。
- 定期检查日志文件大小，必要时进行轮转（目前未自动轮转，可自行编写脚本）。

## 备份建议

- 定期备份 `updates/data/versions.json`（版本元数据）。
- 定期备份 `updates/snapshots/` 目录（版本快照）。
- 如果你的游戏文件不经常变化，可以备份 `public/` 目录。

这些数据丢失后，虽然可以重新扫描 `public/` 并重新生成版本，但历史版本信息会丢失，客户端可能无法正确增量更新。
